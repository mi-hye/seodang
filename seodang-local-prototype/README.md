```bash
cd /Users/kangmihye/Desktop/study/seodang/seodang-local-prototype

```

**컴퓨터와 휴대폰을 같은 신뢰할 수 있는 네트워크에 연결하고, 터미널의 Network 주소를 휴대폰 브라우저에서 여세요. 컴퓨터의 서버는 실행 상태로 두세요.**

2026-10-15 이 컴퓨터에서 실제 확인한 Wi-Fi(en1) 주소는 **http://192.168.1.118:5173/** 입니다. 예시 IP가 아닙니다. 네트워크가 바뀌면 주소도 바뀔 수 있으니 새로 실행한 터미널을 우선 확인하세요. `utun6`에 출력된 주소는 VPN 인터페이스이므로 휴대폰 안내에 사용하지 않았습니다. 이 컴퓨터에서 LAN 주소 접속은 확인했으며 **실제 휴대폰 접속은 사용자 확인 대기**입니다.

| 목적                 | 명령                                     | 접속 방법                             |
| -------------------- | ---------------------------------------- | ------------------------------------- |
| 컴퓨터에서만 개발    | `npm run dev`                            | 컴퓨터의 http://localhost:5173/       |
| 휴대폰 개발 화면     | `npm run dev:lan`                        | 터미널의 Network 주소, 기본 5173      |
| 캐릭터 반응 테스트   | `npm run dev:lan`                        | Network 주소 뒤에 `/?debug=1` 추가    |
| 컴퓨터 빌드 미리보기 | `npm run build` 후 `npm run preview`     | http://localhost:4173/                |
| 휴대폰 빌드 미리보기 | `npm run build` 후 `npm run preview:lan` | 해당 터미널의 Network 주소, 기본 4173 |
| 종료                 | 서버 터미널에서 `Ctrl+C`                 | 이후 접속·새로고침 불가               |

이미 서버가 켜져 있으면 다시 실행할 필요가 없습니다. 포트 충돌 시 기존 프로세스를 종료하지 말고 `npm run dev:lan -- --port 5174`를 사용하세요. 컴퓨터 전용은 `npm run dev -- --port 5174`, 미리보기는 `npm run preview:lan -- --port 4174`처럼 변경할 수 있습니다. `--strictPort` 때문에 포트가 자동으로 변경되지 않습니다.

`localhost`와 `127.0.0.1`은 접속하는 기기 자신입니다. 휴대폰에서 컴퓨터를 여는 주소가 아닙니다. `0.0.0.0`은 서버의 수신 설정이지 주소창에 넣을 목적지 주소가 아닙니다. 컴퓨터의 실제 LAN IP와 포트를 사용하세요. HTML 파일을 더블클릭하거나 휴대폰에 Node·Expo Go·앱을 설치할 필요는 없습니다.

첫 의존성 설치에는 인터넷이 필요합니다. 설치 후 플레이는 외부 API, 계정, 키, 이미지·폰트 CDN을 사용하지 않지만, 컴퓨터와 휴대폰 사이 로컬 네트워크와 서버는 계속 필요합니다. 컴퓨터가 절전하거나 서버가 종료되면 이미 열린 일부 화면만 동작할 수 있으며 독립 오프라인 실행을 의미하지 않습니다. PWA·서비스 워커·외부 배포·공개 터널은 없습니다.

## 구현 범위

독립 React + TypeScript + Vite 실험입니다. 기존 Expo 서당 앱의 소스·설정·잠금 파일·환경 변수·네이티브 프로젝트를 변경하지 않았습니다. 별도 package.json, lockfile, node_modules를 사용합니다. 기존 운영 서비스 호출, Supabase 연결, 커밋·푸시·배포는 하지 않았습니다. 캐릭터·사건·색상은 테스트용 제안이며 공식 세계관이나 브랜드로 확정한 것이 아닙니다.

- 시작 대사 → 책상 쪽지 해석 → 선반 메모 해석 → 파란 상자에서 열쇠 챙기기 → 책상 서랍 열기 → 결말·문장 복습.
- 배경 내 HTML 조사 버튼 3개, 직접 그린 SVG 서재와 기존 서당 앱에서 가져온 픽셀 서당개. 그림 밖 카드 목록으로 조사를 대체하지 않습니다.
- 서당개 idle / talking / happy / thinking / surprised. 눈·몸·꼬리·머리·입이 따로 반응하며 같은 반응도 재생됩니다. 애니메이션은 사건 전이와 독립적입니다.
- 오답 힌트·재시도·도움말, 이미 해석한 단서만 보여 주는 기록, 읽기 보조, 시스템 동작 선호·동작 줄이기.
- 단계 기반 진행, 즉시 저장, 이어하기·완료 결과 보기·확인 후 재시작. 손상된 저장 검증과 저장 실패 시 메모리 플레이.
- 44px 이상 버튼, native dialog 포커스 제한·Escape 닫기·복귀, 세로 스크롤, safe-area, `100dvh`, 브라우저 확대 허용.

## 번들

새 독립 프로젝트이므로 기존 앱과 비교할 동일 생산 빌드 기준선은 없습니다. 데스크톱·모바일은 같은 진입 파일입니다. 프로덕션에서 초기 JS gzip 약 **78.33KB**, 초기 CSS gzip **3.57KB**, 선택적 설정·단서·재시작 청크 gzip **1.27KB**입니다. 온보딩은 별도 JS **2.38KB**와 CSS **1.29KB**로 분리되어 첫 방문 또는 다시 보기 때 로드합니다. 첫 방문의 총 JS는 약 **80.71KB**, CSS는 **4.86KB**이며 전체 선택적 청크까지 합한 JS는 **81.98KB**입니다. 이전 구현 대비 공통 초기 JS는 +0.82KB, CSS는 +0.13KB입니다. 공통 및 모달 CSS는 초기 CSS에 포함됩니다. 초기 핵심 장면·스토리·작은 캐릭터는 즉시 로딩하고 보조 패널은 lazy import로 분리했습니다. 개발 패널은 프로덕션 출력에서 제외됩니다. 게임 엔진, 라우터, UI·애니메이션 라이브러리는 추가하지 않았습니다.

## 저장과 초기화

- `seodang-local-prototype:case-01:v1`: 사건 단계·오답·힌트.
- `seodang-local-prototype:settings:v1`: 읽기·동작 설정.
- `seodang-local-prototype:onboarding:v1`: 시작 안내 완료 여부.

게임 화면에서 설정 → 처음부터 다시 시작 → 확인으로 사건만 초기화하세요. 설정은 유지됩니다. 모든 데이터를 초기화하려면 브라우저 개발 도구의 저장소 화면에서 **위 세 키만** 삭제하세요. 다른 앱의 키나 저장소 전체를 지우지 마세요. `localStorage.clear()`는 사용하지 않습니다.

저장은 브라우저와 origin별입니다. `localhost`, LAN IP, 다른 포트, 다른 기기 간에 공유·동기화되지 않습니다. IP나 포트가 바뀌면 이어하기가 없는 것처럼 보일 수 있습니다. 저장 실패 안내가 보이면 현재 세션은 플레이할 수 있지만 새로고침 이후 복구는 보장하지 않습니다.

## 다른 컴퓨터로 옮기기

이 폴더의 소스·로컬 자산·package.json·package-lock.json·설정 파일을 복사하세요. 기존 서당 앱이나 환경 변수는 필요 없습니다. 새 컴퓨터에서 문서화된 Node LTS로 `npm ci`, `npm run dev:lan`을 실행하세요. 운영체제가 다른 곳으로 node_modules를 복사해 재사용하지 마세요. dist는 `npm run build`로 다시 만들 수 있습니다.

MD 지시서만 옮겼다면 먼저 프로젝트 구현이 필요합니다. 지시서 자체는 실행 가능한 앱이 아닙니다.

## 접속이 안 될 때

1. **실행 확인:** `npm run dev:lan`이 실행 중인지, 오류나 포트 충돌이 없는지 확인한다. 포트가 점유되어 있으면 다른 프로세스를 종료하지 말고 `npm run dev:lan -- --port 5174`로 다른 포트를 사용한 뒤 주소도 맞춘다.
2. **주소 확인:** 컴퓨터에서도 Network 주소를 열어 본다. 휴대폰에는 `localhost`가 아니라 같은 Network 주소를 입력한다. IP·포트·`http://`를 다시 확인한다.
3. **네트워크 확인:** 휴대폰이 모바일 데이터만 사용하는 상태가 아닌지, 같은 LAN인지 확인한다. 게스트 Wi-Fi·회사/공용 Wi-Fi의 기기 간 격리나 VPN 경로가 원인일 수 있다. 우선 개인의 신뢰할 수 있는 네트워크에서 재현한다.
4. **방화벽 확인:** 필요한 경우 사용자가 운영체제의 Node 또는 해당 개발 포트에 대한 로컬 네트워크 접근 허용 상태를 확인하게 한다. 전체 방화벽 끄기나 보안 정책 우회를 안내하지 않는다.
5. **실행 환경 확인:** WSL2·Docker·원격 개발 환경의 내부 주소를 사용자 컴퓨터의 LAN 주소로 착각하지 않는다. 이번 기본 경로는 사용자 컴퓨터에서 직접 실행하는 것이다. WSL2는 `--host`만으로 LAN 접근이 해결되지 않을 수 있으므로 필요할 때 해당 환경의 공식 문서를 확인한다. 임의의 네트워크 재설정은 하지 않는다.
6. **화면 오류와 연결 실패 구분:** 접속 자체가 안 되는 문제와, 페이지는 열리지만 JavaScript 오류로 하얗게 보이는 문제를 구분한다. 후자는 실제 브라우저 오류·자산 경로·브라우저 지원 범위를 점검한다. 호스트 허용이나 CORS 설정을 무조건 풀지 않는다.

IP 접속은 Vite 기본 허용 범위입니다. allowedHosts: true, cors: true, 전체 방화벽 끄기, 공인 IP 노출, 포트 포워딩, 공개 터널은 사용하지 않습니다.
