# 오늘의 수업 서버 확장 (1차)

## 반영 범위

- `daily_lessons`: 한국 날짜 × 2–5단계의 검수 완료 문제 3개를 저장한다.
- 1단계(`starter`): 개인 쓰기 이력과 복습 기한으로 기기에서 구성한다. 서버 문제를 기다리지 않는다.
- 2·3단계(`kana`, `words`): 서버가 제공한 학습 순서의 새 문제와, 완료한 문제 중 기한이 된 복습 최대 1개를 섞는다. 복습 간격은 1·3·7·14·30일이다.
- 4·5단계(`sentences`, `advanced`): 그날 검수된 독해 지문·4지선다 문제를 사용한다.
- 서버 콘텐츠 날짜는 `Asia/Seoul`. 기존 사용자 학습일·간식 한도는 기기의 현지 날짜를 그대로 유지한다.
- 시작한 수업은 문제·선택지 순서까지 기기에 저장한다. 재접속·서버 변경으로 교체하지 않는다. 설정에서 명시적으로 난이도를 변경하면 기존 동작대로 새 수업을 시작한다.
- 통신 오류/콘텐츠 미준비 시 재시도 또는 **저장된 기본 문제로 연습하기**를 제공한다. 고정 샘플을 새 서버 콘텐츠로 가장하지 않는다. 기본 연습을 선택해도 그날 수업은 고정된다.
- 새 의존성 없음. 수업 화면의 기존 lazy 경계를 유지한다.

## 공개/검수 경계

앱은 anon 키로 SELECT만 할 수 있다. 쓰기 권한은 서버 전용이며, `review_status=approved`이고 한국 날짜가 도래한 행만 공개한다. 기존 `daily_readings`도 같은 공개 조건으로 강화했다.

DB는 JSON 구조, 단계별 모드/선택지/정답, 검수자 정보, 승인본 불변성을 검사한다. 정답의 교육적 타당성이나 번역 품질까지 자동 증명하지는 않으므로 **실제 독립 검수**가 반드시 필요하다. 검수자 이름만 바꾸는 것을 독립 검수로 취급하면 안 된다.

한 문제의 ID는 `server:<stage>:<concept>-v<revision>` 형식이다. 같은 ID의 문제 내용을 수정하면 안 된다. 독해 문제는 ID에 날짜도 넣는다. 승인본 재게시/덮어쓰기는 금지한다. 앱 버그로 잘못 공개된 문제를 숨겨야 할 때는 별도 운영 대응이 필요하다.

## 로컬 생성 자동화

2026-10-06 사용자 요청으로 클라우드 이전 대신 기존 로컬 자동화 `automation-2`를 수정했다. 이름은 **매일 독해·오늘의 수업 생성 및 독립 검수**, 상태는 ACTIVE이며 기존 대상 채팅과 실패 시에만 알림 설정은 유지한다.

로컬 작업은 매일 **23:55 KST**에 다음 날 독해 3레벨과 수업 4단계 생성을 시작한다. 이는 시작 시각이며 자정 전 완료를 보장하지 않는다. Mac과 Codex 앱이 실행 중이고 이 저장소가 접근 가능해야 한다. 날짜는 실행 시작 때 한 번 계산하고 재시도 중 자정을 넘어도 같은 대상을 유지한다. 지연 실행은 원래 예약 회차의 대상 날짜를 기준으로 하며, 예약 시각을 알 수 없는 자정 이후 실행은 누락된 오늘분부터 확인한다.

수업 생성 순서:

1. 최근 6개월 콘텐츠 및 날짜/단계별 게시 여부 조회. 이미 승인된 대상은 재생성/수정하지 않는다.
2. 단계별 학습 순서를 `curriculum_note`에 기록하고 문제 3개씩 생성. 2·3단계는 순서가 있는 기초 단어·문장, 4·5단계는 새 지문과 추론/독해 문제. 현재는 개인별 전체 커리큘럼 진도 서버 동기화가 아니라 일별 공통 패키지 + 기기별 복습이다.
3. 별도의 검수 단계에서 정답 유일성, 오답, 한/일 질문·힌트, 단계 차이, 최근 지문 중복을 검수한다. 불합격은 수정·재검수한다.
4. 네 단계 모두 통과한 뒤 한 번에 INSERT. 승인된 행의 upsert 금지.
5. 서버 자격으로 다시 읽어 네 단계 `approved`와 실제 저장된 문제를 대조한다. 다음 날 콘텐츠는 공개 API에서 아직 보이지 않는 것이 정상이다.

각 행의 형식:

```json
{
  "lesson_date": "YYYY-MM-DD",
  "stage": "kana",
  "schema_version": 1,
  "curriculum_note": "이번 수업의 목표와 학습 순서",
  "generator": "실제 생성 주체",
  "reviewer": "실제 독립 검수 주체 (generator와 달라야 함)",
  "reviewed_at": "검수 완료 ISO timestamp",
  "review_status": "approved",
  "review_notes": ["실제 검수 결과"],
  "questions": [
    {
      "id": "server:kana:concept-v1",
      "mode": "choice",
      "cue": "일본어/그림 단서",
      "prompt": {"ko": "질문", "ja": "質問"},
      "choices": ["선택지1", "선택지2", "선택지3"],
      "answer": ["선택지1"],
      "hint": {"ko": "정답 해설", "ja": "解説"}
    }
  ]
}
```

위 예시는 **형식 설명**이며 게시 가능한 실제 문제가 아니다. 실제 입력은 4개 행 배열이고 각 행에 정확히 3문제가 필요하다. `order`는 중복 없는 모든 선택지를 정답 순서로 포함한다. 긴 독해는 `choice`, 선택지 4개, 60자 이상 단서가 필요하다. 길이 검사는 최소 구조 검사이며 난이도 품질을 보증하지 않는다.

Node 22.15+ 환경에서:

```sh
npm run daily-lesson:publish -- reviewed-lessons.json
npm run daily-lesson:publish -- reviewed-lessons.json --check
npm run daily-lesson:publish -- reviewed-lessons.json --publish
```

기본은 로컬 형식 검증만, `--check`는 서버 중복 확인까지 하되 쓰지 않음, `--publish`는 중복 없는 INSERT 후 재조회한다. 환경 변수 `EXPO_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 기존 로컬 `.env` 또는 실행 환경에서 공급한다. 키를 프롬프트/저장소/클라이언트로 전달하지 않는다.

독해는 기존 `daily-reading:publish`의 어휘 전수 검증 및 별도 검수 담당의 승인을 유지한다. 승인된 날짜는 건너뛰고, 독해가 일부 레벨만 게시된 경우 기존 스크립트의 upsert로 덮어쓰지 않도록 중단·보고한다. 수업은 이미 승인된 행을 그대로 포함해 누락 단계만 보완한다. 실제 독립 검수 실행이 불가능하면 게시하지 않는다.

## 보관 정책

사용자 선택: 매일 한국 날짜 기준 **6개월보다 오래된 콘텐츠**를 삭제한다. 180일로 근사하지 않는다. 경계 날짜와 이후 데이터는 유지한다.

- 작업: `seodang-learning-content-retention`, 서버 Cron, 매일 **00:20 KST**.
- 범위: `daily_readings.reading_date`, `daily_lessons.lesson_date`만. 한자 사전, 개인 학습 이력, 강아지 성장/보상 제외.
- 기기에서 시작한 수업과 저장된 복습 문제는 서버 원본이 삭제돼도 유지한다 (복습 스냅샷은 최근 120개).
- 삭제는 앱에서 복원할 수 없다. 복구가 필요하면 별도로 확보한 DB 백업이 필요하다.
- 비활성화: 관리자가 `cron.alter_job`으로 해당 이름의 작업만 비활성화한다.
