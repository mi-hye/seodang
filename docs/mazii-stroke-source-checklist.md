# Mazii Stroke Source Checklist

## 1. 목적

`Mazii`를 `KanjiVG` 보완용 한자 획 데이터 소스로 사용할 수 있는지 판단하기 위한 조사 체크리스트다.

이 문서는 아직 구현 문서가 아니다. 나중에 실제 조사할 때 `된다 / 안 된다 / 불명`으로 채우기 위한 기준표다.

## 2. 현재 전제

- 현재 앱의 쓰기 연습 데이터는 `kanji_characters` + `kanji_strokes`를 기준으로 동작한다.
- 현재 DB의 연습 가능 한자 수는 `6431`개다.
- `KANJIDIC2` 기반 메타데이터는 `12559`개까지 확보되어 있다.
- 부족한 것은 `뜻`보다 `stroke`다.

즉, `Mazii` 검토의 핵심 질문은 이것이다.

`Mazii`에서 `KanjiVG`에 없는 한자의 획 데이터까지 안정적으로 확보할 수 있는가?

## 3. 선행 결론

- `Mazii`는 한자 상세 페이지에서 `strokes`, `radicals`, `onyomi`, `kunyomi`, 예시 단어를 노출한다.
- 공개 웹 UI 기준으로 stroke order animation 성격의 기능이 존재하는 것으로 보인다.
- 다만 이 사실만으로 `대량 수집 가능`, `라이선스 안전`, `파이프라인 안정`이 보장되지는 않는다.

## 4. 조사 항목

### A. 실제 커버리지

확인 질문:

- `KanjiVG`에 없는 한자도 `Mazii`에 존재하는가
- 존재한다면 몇 개까지 확인 가능한가
- 상용한자 밖의 이체자, 구자체, 확장 한자도 포함하는가

체크:

- `KANJIDIC2 reviewOnly` 샘플 50개로 검색
- 검색 성공/실패 수 기록
- `JLPT N1` 밖 희귀 한자 샘플도 포함

판정 기준:

- `성공률 80% 이상`: 후보 유지
- `성공률 50~79%`: 보조 소스만 가능
- `성공률 50% 미만`: 실질적 확장 소스로 부적합

### B. 획 데이터 존재 여부

확인 질문:

- 단순 stroke count만 있는지
- 실제 `stroke order`가 있는지
- 실제 `path/vector` 데이터가 있는지
- 이미지/캔버스만 있고 구조화 데이터는 없는지

체크:

- 상세 페이지 DOM 확인
- 네트워크 요청 확인
- JSON/XHR 응답 유무 확인
- SVG path, 좌표, 순서 정보가 있는지 기록

판정 기준:

- `구조화된 path/order 데이터 존재`: 가장 좋음
- `애니메이션만 있고 좌표 추출 어려움`: 위험
- `stroke count만 존재`: 연습용 소스로 부적합

### C. 추출 안정성

확인 질문:

- 데이터가 서버 응답 JSON으로 내려오는가
- 페이지 렌더링이 자주 바뀌어도 유지 가능한 구조인가
- 인증, 봇 차단, 속도 제한이 강한가

체크:

- 비로그인 상태 접근 가능 여부
- 직접 URL 접근 규칙 확인
- 동일 요청 반복 시 응답 안정성 확인
- 모바일/웹 응답 차이 확인

판정 기준:

- `정적이거나 예측 가능한 API 응답`: 안정
- `렌더 후 난독화된 프런트 상태만 존재`: 불안정
- `강한 rate limit 또는 차단`: 장기 운영 부적합

### D. 라이선스와 이용조건

확인 질문:

- 데이터 재사용이 허용되는가
- 교육 목적이어도 복제/재배포가 금지되는가
- 상업적 사용 제한이 있는가

현재 확인한 점:

- [Mazii Terms](https://mazii.net/terms-of-user.html)에는 서비스와 지식재산권이 `EUP` 및 그 라이선서에 귀속된다고 적혀 있다.
- 같은 문서에는 `Mazii` 이름, 그래픽, 로고 등의 사용 권리가 자동으로 부여되지 않는다고 적혀 있다.
- 이 수준만으로 데이터 재사용 허용이라고 해석하면 안 된다.

체크:

- 이용약관 원문 재검토
- 별도 API/데이터 라이선스 공개 여부 확인
- 필요 시 문의 채널 존재 여부 확인

판정 기준:

- `명시적 허용`: 사용 가능
- `금지 또는 불명확`: 자동 수집/적재 보류

### E. 데이터 품질

확인 질문:

- stroke order가 일본 학습 기준과 맞는가
- 동일 한자에서 변형이 과도하지 않은가
- 우리 현재 `kanji_strokes` 스키마로 변환 가능한가

체크:

- 샘플 20자 수동 비교
- `KanjiVG`와 공통 한자 비교
- path 단위 분해 가능 여부 확인

판정 기준:

- `현재 스키마로 무리 없이 변환`: 적합
- `이미지 기반 재해석 필요`: 구현 비용 큼

## 5. 조사 순서

1. `reviewOnly` 한자 샘플 50개 선정
2. `Mazii` 검색 성공률 확인
3. 상세 페이지에서 실제 stroke 데이터 구조 확인
4. 네트워크 응답에 구조화 데이터가 있는지 확인
5. 라이선스/이용약관 재사용 가능성 확인
6. 가능하면 PoC 5자 변환
7. 같은 시점에 `meaning_ko`, `meaning_ja`가 `뜻미상`으로 남아 있는 항목 보강 대상도 함께 추출

## 6. 성공 조건

아래를 모두 만족해야 실제 소스 후보로 채택한다.

- `KanjiVG`에 없는 한자를 의미 있게 보완한다
- 실제 stroke order 데이터를 얻을 수 있다
- 반복 수집이 기술적으로 안정적이다
- 라이선스 리스크가 낮다
- 현재 `kanji_characters` / `kanji_strokes` 구조로 변환 가능하다

## 7. 실패 시 대안

`Mazii`가 부적합하면 아래 방향으로 간다.

- `연습 가능 한자`와 `사전형 한자`를 분리
- stroke가 없는 한자는 `검색/뜻/읽기 전용`으로 제공
- stroke 확장 소스는 다른 공개 데이터셋을 재탐색
- `뜻미상` 항목은 별도 의미 보강 파이프라인으로 분리
