# 일본어 한자 쓰기 학습 앱 MVP 설계 문서

## 1. 제품 개요

이 앱은 두 가지 주요 사용자층을 대상으로 한다.

- 일본어 한자 쓰기를 연습하려는 한국인 학습자
- 학교 한자 학습을 반복 연습해야 하는 일본 초중등 학생

초기 목표는 "한자를 정확한 순서로 직접 써 보고, 반복 복습할 수 있는 모바일 학습 앱"을 만드는 것이다.
장기적으로는 단순 학습 앱을 넘어, 게임형 학습 모드와 점수 시스템을 붙일 수 있는 구조를 목표로 한다.

초기 버전에서는 게임보다 학습 코어를 우선한다.

- 한자 콘텐츠
- 획순 확인
- 따라 쓰기
- 결과 피드백
- 복습 관리

이 코어가 안정적으로 작동해야 이후에 떨어지는 한자를 쓰는 모드, 제한 시간 모드, 콤보 모드 같은 게임 요소를 자연스럽게 확장할 수 있다.

## 2. 제품 목표

### 핵심 목표

- 사용자가 모바일에서 일본어 한자를 직접 써 보며 반복 학습할 수 있게 한다.
- 한자별 학습 기록을 저장해 복습 흐름을 만든다.
- 한국인 학습자와 일본 초중등 학습자 모두가 사용할 수 있는 공통 학습 코어를 만든다.
- 이후 게임 모드 확장을 고려한 구조로 설계한다.

### 비핵심 목표

초기 MVP에서는 아래 항목을 우선하지 않는다.

- 정교한 손글씨 AI 인식
- 실시간 멀티플레이
- 캐릭터/아바타 중심 게임 시스템
- 교사용 관리자 페이지
- 유료 결제/구독

## 3. 대상 사용자

### 사용자군 A: 한국인 일본어 학습자

특징:

- 일본어 독해와 쓰기를 함께 익히고 싶다.
- 한자의 뜻, 음독/훈독, 예문이 중요하다.
- JLPT, 빈출 어휘, 테마별 학습이 유용하다.

니즈:

- 뜻과 읽기를 함께 확인하고 싶다.
- 손으로 써 보며 암기하고 싶다.
- 자주 틀린 한자를 자동 복습하고 싶다.

### 사용자군 B: 일본 초중등 학생

특징:

- 학교 학년별 한자 학습과 반복 쓰기 훈련이 필요하다.
- 숙제형 반복 훈련과 빠른 피드백이 중요하다.
- 복잡한 기능보다 단순하고 직관적인 UX가 필요하다.

니즈:

- 학년별 한자를 순서대로 연습하고 싶다.
- 획순과 쓰기 정확도를 확인하고 싶다.
- 틀린 글자만 다시 모아서 반복하고 싶다.

### 공통 니즈

- 한자를 직접 써 보는 경험
- 획순 확인
- 반복 복습
- 성취감 있는 진도 관리

## 4. 문제 정의

기존 한자 학습은 보통 다음 한계를 가진다.

- 단순 암기 중심이라 직접 쓰기 연습이 약하다.
- 획순 피드백이 부족하다.
- 사용자 수준에 맞는 반복 복습 흐름이 약하다.
- 게임형 학습이 있더라도 학습 품질보다 자극 중심인 경우가 많다.

이 앱은 "직접 쓰기"를 중심에 두고, 학습 정확도와 반복 훈련을 우선하는 구조를 지향한다.

## 5. 제품 원칙

1. 학습 코어 우선
2. 게임은 학습 코어 위에 얹는다
3. 사용자에게 즉각적인 피드백을 준다
4. 한 번 만든 코어 로직은 여러 모드에서 재사용한다
5. 주니어 개발자가 유지 가능한 단순한 구조를 우선한다

## 6. MVP 범위

### 반드시 포함

- 한자 목록 보기
- 한자 상세 보기
- 획순 애니메이션 보기
- 따라 쓰기 화면
- 간단한 정답/오답 피드백
- 학습 기록 저장
- 틀린 한자 다시 보기

### 있으면 좋지만 2순위

- 음독/훈독 오디오
- 난이도 필터
- 즐겨찾기
- 일일 목표
- 연속 정답 카운트

### MVP에서 제외

- 자유 손글씨 인식 AI
- 소셜 기능
- 랭킹
- 고급 게임 모드
- 서버 기반 실시간 동기화

## 7. 핵심 사용자 시나리오

### 시나리오 1: 한국인 학습자

1. 앱을 연다.
2. JLPT 또는 테마별 한자 목록을 본다.
3. 한자를 선택한다.
4. 뜻, 읽기, 예문, 획순을 확인한다.
5. 직접 써 본다.
6. 결과 피드백을 보고 틀린 한자를 복습 목록에 넣는다.

### 시나리오 2: 일본 초중등 학생

1. 앱을 연다.
2. 학년별 한자 세트를 선택한다.
3. 오늘의 학습 목록을 시작한다.
4. 획순을 보고 따라 쓴다.
5. 틀린 글자는 다시 연습한다.
6. 완료 후 진도와 점수를 확인한다.

## 8. 화면 구조

초기 MVP 화면은 5개 정도로 제한한다.

### 1. 홈

- 오늘의 학습 시작
- 최근 학습 이어하기
- 복습이 필요한 한자 수 표시
- 사용자 그룹별 진입 버튼

### 2. 한자 목록

- 학년별 / JLPT별 / 테마별 필터
- 검색
- 학습 여부 표시

### 3. 한자 상세

- 한자
- 뜻
- 음독/훈독
- 예문
- 획수
- 획순 보기
- 쓰기 연습 시작 버튼

### 4. 쓰기 연습

- 제시 한자
- 참고 획순
- 입력 캔버스
- 현재 획 수 표시
- 다시 쓰기
- 제출

### 5. 결과 / 복습

- 성공/실패
- 어떤 부분이 틀렸는지 간단한 피드백
- 다시 연습
- 다음 한자
- 복습 목록에 추가

## 9. 정보 구조와 데이터 모델

초기 설계에서 데이터와 로직을 분리해야 나중에 게임 모드 확장이 쉽다.

### 엔티티 1: Character

```ts
type Character = {
  id: string;
  literal: string;
  meaningKo?: string;
  meaningJa?: string;
  onyomi: string[];
  kunyomi: string[];
  grade?: number;
  jlptLevel?: string;
  strokeCount: number;
  radical?: string;
  examples: Example[];
  strokeDataId: string;
};
```

### 엔티티 2: Example

```ts
type Example = {
  word: string;
  reading: string;
  meaningKo?: string;
  meaningJa?: string;
};
```

### 엔티티 3: StrokeData

```ts
type StrokeData = {
  id: string;
  characterId: string;
  strokes: Stroke[];
};

type Stroke = {
  order: number;
  points: { x: number; y: number }[];
};
```

### 엔티티 4: PracticeAttempt

```ts
type PracticeAttempt = {
  id: string;
  characterId: string;
  createdAt: string;
  totalStrokes: number;
  correctStrokes: number;
  score: number;
  passed: boolean;
  durationMs: number;
};
```

### 엔티티 5: ReviewItem

```ts
type ReviewItem = {
  characterId: string;
  wrongCount: number;
  lastPracticedAt?: string;
  nextReviewAt?: string;
  priority: number;
};
```

## 10. 기술 설계 방향

### 추천 스택

- React Native
- Expo
- TypeScript
- Expo Router 또는 React Navigation
- Zustand
- SQLite 또는 AsyncStorage

### 추천 이유

- iOS와 Android를 함께 대응하기 쉽다.
- 주니어가 생산성을 확보하기 좋다.
- 추후 애니메이션, 제스처, 캔버스 입력도 확장 가능하다.
- 웹 React 경험이 있다면 학습 전환 비용이 낮다.

### 상태 분리 원칙

초기부터 상태를 아래처럼 나누는 편이 좋다.

- content state: 한자/콘텐츠 데이터
- practice state: 현재 쓰기 세션 상태
- progress state: 학습 기록, 복습 상태
- settings state: 언어, 난이도, 사용자 타입

## 11. 아키텍처 원칙

이 프로젝트는 처음부터 아래 4계층으로 나누는 것을 권장한다.

### 1. Content

- 한자 데이터
- 예문 데이터
- 획순 데이터

### 2. Practice Engine

- 사용자의 stroke 입력 처리
- stroke 순서 비교
- 간단한 정확도 계산
- pass/fail 판정

### 3. Progress

- 학습 이력 저장
- 오답 누적
- 복습 우선순위 계산

### 4. Game Mode

- 시간 제한 규칙
- 점수 시스템
- 콤보
- 특수 이벤트

핵심은 `Practice Engine`을 게임 로직과 분리하는 것이다. 그래야 일반 학습 화면과 게임 모드에서 같은 판정 로직을 재사용할 수 있다.

## 12. 쓰기 판정 로직의 초기 전략

초기에는 고급 AI 판정보다 단순하고 설명 가능한 판정이 낫다.

### 1차 MVP 판정 기준

- 획 수가 맞는가
- 획 순서가 대체로 맞는가
- 시작점/끝점이 허용 오차 안에 있는가
- 전체 형태가 크게 벗어나지 않았는가

### 이유

- 디버깅이 쉽다.
- 사용자가 왜 틀렸는지 설명하기 쉽다.
- 주니어 개발자가 구현하고 개선하기 좋다.

### 나중에 고도화할 수 있는 방향

- 곡선 유사도 비교
- 획 길이/방향 비교
- 개인별 난이도 보정
- 손글씨 분류 모델 보조

## 13. 게임 확장 방향

장기적으로는 다음 모드들을 붙일 수 있다.

### 게임 모드 A: 떨어지는 한자 제거

- 화면 위에서 한자가 떨어진다.
- 제한 시간 안에 해당 한자를 써서 제거한다.
- 빠를수록 추가 점수를 준다.

### 게임 모드 B: 연속 필사 챌린지

- 정해진 시간 동안 최대한 많이 맞춘다.
- 연속 정답 시 콤보 보너스를 준다.

### 게임 모드 C: 학교 시험 대비 모드

- 학년별 문제 묶음을 순서대로 푼다.
- 오답 중심 재시험을 제공한다.

### 설계상 주의점

- 게임 규칙은 별도 레이어에 둔다.
- 한자 데이터와 쓰기 판정 로직은 재사용한다.
- MVP 단계에서 게임 구현까지 욕심내지 않는다.

## 14. AI 활용 전략

이 프로젝트에서 AI는 앱 사용자용 기능보다, 개발자 생산성 도구로 우선 활용한다.

### AI를 사용할 영역

- 기획 문서 초안 작성
- 기능 요구사항 정리
- 데이터 모델 설계
- 화면별 컴포넌트 초안 생성
- 타입 정의 작성
- 테스트 코드 초안 생성
- 리팩터링 아이디어 정리
- 코드 리뷰

### AI를 쓸 때 좋은 요청 예시

- "React Native + Expo 기준으로 이 앱의 폴더 구조를 제안해줘"
- "쓰기 연습 화면 상태를 TypeScript 타입으로 설계해줘"
- "이 로직을 주니어도 이해할 수 있게 단순화해줘"
- "이 컴포넌트 테스트 케이스를 작성해줘"
- "이 코드에서 버그 가능성만 리뷰해줘"

### AI를 쓸 때 주의할 점

- AI가 제안한 구조를 그대로 믿지 말고, 항상 단순한지 먼저 본다.
- 앱 핵심 로직은 직접 이해 가능한 수준으로 유지한다.
- 복잡한 추상화와 과도한 최적화는 초기에 피한다.

## 17. 초기 성공 기준

MVP가 아래를 만족하면 1차 성공으로 본다.

- 사용자가 한자 1개를 선택해 상세 정보를 볼 수 있다.
- 획순을 확인한 뒤 직접 써 볼 수 있다.
- 결과에 따라 성공/실패 피드백이 나온다.
- 틀린 한자가 복습 대상으로 저장된다.
- 한국인 학습자와 일본 학생 모두 기본 사용이 가능하다.

## 18. 초기 리스크

### 리스크 1: 손글씨 판정 난이도

대응:

- 초기에는 단순 판정으로 시작한다.
- "완벽한 인식"보다 "일관된 피드백"을 목표로 한다.

### 리스크 2: 콘텐츠 데이터 확보

대응:

- 초반에는 소량의 샘플 데이터로 시작한다.
- 학년별 또는 JLPT별 최소 세트만 먼저 구성한다.

### 리스크 3: 범위 과다

대응:

- 게임 기능은 MVP에서 제외한다.
- 화면 수를 5개 내외로 제한한다.
