# 1단계 히라가나 학습

확정 요구: 난이도 1은 글자를 먼저 배우고 기존 카페 학습은 난이도 2에 배치한다. 1단계부터 확장한다.

구현 범위: 기본 히라가나 46자를 10묶음(あ행, か행, さ행, た행, な행, は행, ま행, や행, ら행, わ・を・ん)으로 나눈다. 각 묶음에서 글자/한국어 읽기 안내, 일본어 기기 TTS, 글자 수만큼 듣기 선택 문제, 오답 재시도, 완료/복습을 제공한다. 한글 읽기는 근사 안내이며 일본어 음성으로 확인한다. 탁음·반탁음·요음·가타카나는 이번 범위에 포함하지 않는다.

앞 묶음의 듣기 문제까지 통과하면 다음 묶음이 열린다. 지도에서 완료한 묶음을 복습하거나 진행 중 수업으로 돌아갈 수 있다. 3글자 묶음도 3문제로 끝나고 중복 선택지가 없다. 같은 소리인 お와 を를 같은 듣기 문제의 보기로 제시하지 않는다.

기존 저장 키와 상위 스키마는 유지한다. kana.version=2에서 active, lessons 배열, learned로 수업별 진행을 보존한다. 기존 단일 첫 수업 기록은 읽을 때 첫 묶음으로 이전하며 기존 원본은 다음 저장 전까지 덮어쓰지 않는다. 초기화하거나 카페 episode/encountered를 변경하지 않는다. 완료한 묶음의 복습은 완료 수를 중복 증가시키지 않고, 다른 수업의 중간 위치를 보존한다. 난이도를 자동으로 2로 바꾸지 않는다.

UI와 CSS의 기존 지연 로딩 유지. 초기 JS gzip 15,938 → 16,952 bytes, 총 JS 22,467 → 24,087 bytes. 공통 CSS 8,631 → 8,790 bytes, kana.css는 별도 로드. 모바일/데스크톱 동일 진입점. 신규 외부 의존성/이미지 없음.

검증: 총 12개 단위 테스트 통과. 전체 46글자 완료, 오답 재시도, 잠금 우회 차단, 3글자 묶음 선택지, 기존 부분/완료 기록 이전, 기록 손상 시 원본 보존, 복습 중 다른 수업 진행 보존, 난이도 변경 시 기록 유지. 브라우저를 열지 않고 DOM 대역으로 실제 앱 이벤트를 실행해 이전 기록의 홈 → 다음 묶음 → 지도 → 이전 묶음 복습 → 진행 중 묶음 재개 → 배운 글자 연결 확인.

## 사건별 학습으로 확장

최신 요구에 따라 10묶음을 카페 안에서 벌어지는 10개 사건으로 전환했다. 사라진 우산 / 뒤섞인 열쇠 / 바뀐 배달 상자 / 사라진 예약표 / 주인 없는 노트 / 직원의 사물함 / 찻잔 진열장의 빈칸 / 마당 화분의 표식 / 뒤바뀐 서랍표 / 마지막 보관 봉투.

흐름: 사건 소개(intro) → 글자 익히기(learn) → 소리 단서(quiz) → 두 글자의 소리와 순서로 물건 찾기(solve) → 사건 해결(summary). 글자를 물건 이름의 번역으로 오해하지 않도록 보관 표식이라고 명시한다. 마지막 물건 선택을 맞히기 전에는 해결 처리하지 않는다. 배경은 기존 카페 에셋을 사용하고, 물건별 선택지는 실제 UI 카드다. 사건별 전용 삽화는 새로 만들지 않았다.

kana.version=3. 기존 v2의 부분 학습 위치와 배운 글자, 완료에 따른 잠금 해제는 보존한다. 기존 완료 수업은 새 사건 소개부터 다시 풀 수 있다. completed는 기존 학습 이수도 포함하며, caseSolved는 새 사건의 실제 해결 여부다. 홈/지도/기록의 사건 해결 수는 caseSolved로 계산한다. 원본은 다음 저장 전까지 보존한다.

전체 이야기 본문(kana-cases.js)은 사건 화면과 함께 지연 로딩한다. 초기 JS gzip 16,952 → 17,519 bytes, 전체 JS 24,087 → 26,689 bytes. 공통 CSS 8,790 → 8,815 bytes; kana.css 별도 로딩 유지. 테스트 13개: 전체 10개 사건 해결, 최종 물건 오답/정답, 기존 v2 기록 이전 및 구분, 잠금/재개/기존 카페 기록 보존. 실제 앱 이벤트를 DOM 대역으로 실행하여 첫 사건 전체부터 다음 사건 진입까지 확인했다.
