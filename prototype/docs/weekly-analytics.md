## 설치·시도·재방문 정의

`distinct_id`는 로그인 사용자가 아닌 동의한 **설치 식별자**다. person profile을 만들지 않으므로 이 운영 정의는 원본 설치 ID로 중복 제거한다. 이벤트 UUID로 전송 중복을 제거한다. 재설치·저장소 삭제·철회 후 재동의·동의 버전 변경은 새 ID를 만들 수 있다. 같은 물리 기기가 여러 ID로 보이는 것을 복구할 수 없으며, 이를 실제 새 기기/새 이용자로 단정하지 않는다. 서로 다른 기기의 동일인도 결합하지 않는다. 동의하지 않은 사람은 관측되지 않는다.

`analytics_enabled`는 관측 참여 시작이며 **설치 날짜가 아니다**. D1/D7은 첫 관측 참여일의 1/7 한국 날짜 뒤에 `learning_progress`가 있는 설치 / 해당 날짜까지 관측 가능한 참여 설치. 생성 쿼리는 2026-10-16 수집 구현 시작일부터 조회한다. 서버 보관 기간 때문에 최초 동의가 소실되면 신규 코호트를 복원하지 말고 계산 불가로 표시한다. 기존 사용자의 첫 동의도 포함되는 ‘참여 후 학습 재방문’ 지표다.

수업 시도는 `(distinct_id, lesson_id, attempt_id)`. 홈에서 진입/이어하기/재학습마다 새 시도, 단계 변화는 같은 시도다. 완료 화면만 열면 시작하지 않는다. 완료는 같은 키의 시작 이후 24시간 이내 `lesson_completed`만 연결한다. 복습이 끼면 복습 종료까지 완료하지 않는다. 24시간 이후 완료는 이 지표에서 제외하고 별도 장기 완료로 점검한다. 단순 전체 완료 수 / 전체 시작 수는 사용하지 않는다. `lesson_exited`는 화면 이동/다시 시작의 **명시적 종료**. 앱 강제 종료·연결 끊김은 명시적 종료가 아니다. 24시간 창 종료 후 완료/종료가 없는 시도는 **미완료 추정**으로만 표시하며 이탈 원인을 확정하지 않는다. 큐 손실도 원인이 될 수 있다.

## 이벤트 계약 v2·v3

허용 목록 외 속성은 삭제한다. 이름·이메일·선택 답·문장·입력 내용·필기 좌표·녹음·화면·URL·오류 메시지를 전송하지 않는다. 분석 ID도 동의 전에는 생성/저장하지 않는다. 현재 v3 수집에는 이전 v1/v2 동의를 자동 승계하지 않는다. 새 안내에서 재동의를 받아야 한다. 동의 철회 시 큐/ID 삭제 및 진행 요청 취소. 기존 서버 데이터는 자동 삭제되지 않는다.

| 이벤트 | 발생 기준 | 추가 속성 |
|---|---|---|
| analytics_enabled | 새 동의 | 공통 속성 |
| app_opened | 동의 후 관측 세션 시작 | 학습 방향/표시 난이도 |
| lesson_started | 수업 진입 | 수업/시도/단계 위치 |
| learning_progress | 실제 단계·문항·매칭 수 변화 | 도착한 위치 |
| lesson_completed | 이번 시도의 최종 복습까지 완료 | 동일 수업/시도 |
| lesson_exited | 학습 화면 이동 또는 수업 다시 시작 | exit_reason: navigation/restart |
| answer_checked | 실제 채점된 제출, 반복 오답 포함 | correct: boolean, 제출 전 위치 |
| step_time | 15초 점검·조작·단계 전환·숨김/이동 시 | active_ms: 0~60000, 해당 위치 |
| audio_playback | 재생 요청 및 종결 결과 | playback_id, audio_source:file/device, audio_result:started/completed/failed/cancelled |

공통: 과거 schema_version=2/consent_version=2, 현재 schema_version=3/consent_version=3, client, environment, platform, app_version, 세션 UUID, 이벤트 원본 시각/UUID. 학습 위치: lesson_id, attempt_id, phase, item_index(0부터), round_index, mode_index, match_count. 표시 난이도 level은 1~5. 동일 문항 키는 수업+단계+item_index+round_index+mode_index; 매칭 문제는 match_count도 함께 확인한다. 자유 입력은 모두 제외. 채점 없는 쓰기/읽기는 정오답 없음. 정상 선택만 하고 확인하지 않은 행동은 제출로 세지 않는다.

오답률은 채점된 제출 중 오답/전체 제출이며 첫 시도 정답률과 다르다. 동일 사용자의 반복 제출이 많을 수 있어 고유 설치 수도 표시한다. 마지막 정답은 복습 가로채기 전 reducer 판정에서 읽는다.

시간은 단조 시계로 누적하고 document visibility/pagehide로 백그라운드를 제외한다. 마지막 pointerdown/keydown 또는 단계 진입 후 60초까지만 센다. 15초 청크의 합을 시도·단계별로 모은 후 중앙값/p90을 구한다. 주 경계에 걸친 시도의 시간은 조회 창 안의 부분 시간이며 전주/이번주를 그대로 전체 수업 시간으로 부르지 않는다. 읽기·듣기에 60초 넘게 조작이 없으면 실제 학습도 제외될 수 있다. OS가 visibility 이벤트를 전달하지 않거나 종료 직전 큐가 유실되면 과소/과대 측정 가능. 집중도·정확한 학습 시간은 아니다.

음성 started는 실제 소리가 났다는 증명이 아니라 재생 요청이다. 실패는 다운로드/재생/TTS 오류 콜백, 취소는 stop/다른 재생/이동/기기 음성 안내 거절이다. mute나 유효하지 않은 entry는 요청이 아니다. 시작과 종결은 playback_id로 연결한다. 실패/요청, 취소/요청, 종결 없음/요청을 분리한다. 중단된 재생을 실패로 더하지 않는다. 콜백 없이 OS에서 음성이 중단되면 구분에 한계가 있다.

## 수집 버전 호환 점검

2026-10-26: 채점과 단계 시간 쿼리는 의미가 호환되는 schema_version IN (2, 3)을 포함한다. 이벤트 UUID 중복 제거, production 필터, 단계별 시간 합산은 유지한다. v3는 유입 속성과 재동의를 추가하며 첫 동의를 신규 설치로 간주하지 않는다.

매주 `schema_coverage`에서 버전별 answer_checked/step_time 이벤트 수를 확인한다. 버전 누락 또는 2·3 외의 버전이 나타나면 계약을 확인하기 전 전체를 대표하는 결과로 보고하지 않는다. 100행 제한에 도달하면 기간을 나누어 조회한다. 채점 결과의 checked 합계는 coverage와 일치해야 한다. 단계 시간의 observed_steps는 청크 수가 아니라 합쳐진 단계 수이므로 coverage의 이벤트 수와 직접 비교하지 않는다.
